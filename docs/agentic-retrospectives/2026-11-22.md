### When missing input caused damage [15]
- Where the owner stepped back too far: the owner approved "Phases 2 and 3 in parallel" without saying that last week's rule still held (one implementer at a time, in the main checkout). The lead read the approval as permission for parallel implementers. It started two worktree agents (#20, #21) without re-checking its own rule.
- Result: the GitHub hook blocked the #21 agent's push from inside its worktree, the same kind of worktree push problem as last week, so its WIP commit (`e689df2`) never left this machine. The #20 agent was stopped with uncommitted work in its worktree. About 30 minutes of agent work was parked, and the owner had to step in twice.
- Guardrail: approving *what* can start doesn't change *how* work runs. When the lead asks about parallel work, it restates the standing process rules in the question. It runs one implementer at a time in the main checkout unless the owner explicitly approves more.
