## Problems (evidence, cost, cause)
1. **Worktree agents couldn't push.**
   - Evidence: #14 and #54 were finished but sat unpushed.
   - Cost: two owner actions and a restart.
   - Cause: `gh-guard.mjs` resolves the script path against the agent's working folder, so from a worktree it pointed at the worktree's copy. `sandbox.excludedCommands` matches only the relative command.
   - Fix: an absolute-path exclusion in `settings.local.json` (owner).
   - Lesson: the lead started parallel worktree agents without first testing a single push from a worktree.
2. **A sandbox placeholder at `.git/config.lock` breaks branch-tracking writes.**
   - Evidence: the #17 agent's branch was created from `dev` and pushed at `b2296ef` instead of `bd9862c`, so PR creation failed with "No commits between". The lead's own branch switches failed halfway as well.
   - The same placeholder also made #16's and #17's agent branches point at `dev` when pushed. The lead re-pointed them with fast-forwards.
   - Open: the owner removes the file.
3. **A Gradle process outside the sandbox (PID 941) held the cache lock.**
   - Evidence: the #16 agent's builds timed out for about 10 minutes.
   - Cause, likely: Gradle hands over a lock with a localhost message, which can't cross the sandbox's private network.
   - Fix: #104.
4. **The lead misdiagnosed missing CI.**
   - Evidence: the lead asked the owner to enable Actions, but the cause was that #100 conflicted with `dev`. Later, a clean-merge check for #17 ran against the stale branch and missed #103's conflict.
   - Lesson: read `Mergeable` (`pr-view`) before diagnosing, and re-check after any branch fix.
5. **A merge into the #16 branch was blocked** because `dev` changed the read-only `.claude/settings.json`. The lead merged from `dev`'s side instead.
6. **The lead's first commit landed on the wrong branch** after a branch switch silently failed. It was caught before pushing and redone on its own branch (#93).
7. **Too much in parallel.**
   - Evidence: four or more streams at once, and many owner interruptions.
   - The owner: "Kind of seems like a lot of things are going roughly."
  - The owner found the session very frustrating (fact reported by the lead).

## Changes made
- Absolute-path sandbox exclusion for the GitHub script (owner, `settings.local.json`).
- A separate agent Gradle home and the allowlisted download host (#104).
- How the lead works from now on:
  - one implementer at a time, in the main checkout;
  - check `Mergeable` and the branch head before reporting or asking the owner;
  - batch owner actions into one message;
  - fewer status updates.
